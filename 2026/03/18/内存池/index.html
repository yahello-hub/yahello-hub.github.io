手撕 C++ 内存池：从原理到实现

在 C++ 开发中，内存管理是绕不开的核心议题，尤其在高频分配 / 释放场景（如服务器、游戏引擎、容器框架）中，传统内存管理方案有三大致命问题：

  • 内存碎片：频繁分配不同大小的内存块后，释放的空间会被分割成大量不连续的小空闲块（外部碎片），或因对齐产生内部碎片，导致内存利用率急剧下降，甚至出现 “内存充足但无法分配大内存” 的窘境。
  • 分配效率低下：new/delete 底层依赖 malloc/free，而 malloc 需要维护复杂的内存元数据、遍历空闲块链表匹配大小，且每次调用可能触发系统调用（brk/mmap），高频分配时性能损耗显著。
  • 线程安全开销：标准库 malloc 为保证线程安全，采用全局锁设计，多线程并发分配时会产生严重的锁竞争，导致性能瓶颈（如高并发服务器中，内存分配可能占总耗时的 30% 以上）。

内存池是什么

内存池（Memory Pool）是一种预分配 - 复用的内存管理模式，内存池的核心是 “池化思想”，即将分散的内存资源集中管理，避免频繁与系统内核交互。其核心组件包括：

  • 内存池管理器：负责内存池的初始化、动态扩容、销毁，以及空闲内存块的调度。
  • 空闲块链表（FreeList）：维护未被使用的内存块，分配时从链表头部取块（O (1) 操作），释放时将块插入链表头部（O (1) 操作）。
  • 元数据：记录内存块的大小、是否空闲、前后块指针等信息（嵌入式设计，无额外内存开销）。
  • 对齐规则：将不同大小的内存申请映射到固定尺寸的块（如 8/16 字节对齐），平衡内部碎片与分配效率。

并发内存池

基础内存池在多线程场景下，因全局锁会产生严重的锁竞争（如 8 线程并发分配时，锁等待可能占总耗时的 50% 以上）。工业级并发内存池采用三级缓存结构，核心目标是：

  • 每个线程拥有独立的 Thread Cache（线程本地存储 TLS），分配 / 释放无需锁（无竞争）。
  • Thread Cache 仅在空闲块耗尽时，向 Central Cache 批量申请块（减少锁竞争次数）。
  • Central Cache 管理中等粒度的内存块，采用细粒度锁（每个大小等级一个锁），向 Page Cache 申请连续物理页。
  • Page Cache 管理物理页，向系统申请内存（mmap/VirtualAlloc），并支持空闲页合并（彻底消除外部碎片）。

（1）ThreadCache 类结构

Thread Cache 是线程本地存储（TLS），每个线程一个实例，无需锁。核心结构是空闲链表数组，每个链表对应一种对齐后的对象大小。

（2）CentralCache 类结构（单例模式）

Central Cache 是全局唯一的，管理中等粒度的内存块，核心结构是 SpanList 数组（每个 SpanList 对应一种对象大小），采用细粒度锁（每个大小等级一个锁）

（3）PageCache 类结构（单例模式）

Page Cache 管理物理页，核心结构是 SpanList 数组（每个 SpanList 对应一种页数的 Span），支持空闲页合并（彻底消除外部碎片）
