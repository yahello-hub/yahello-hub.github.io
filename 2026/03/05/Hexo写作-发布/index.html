用 Typora 打开编辑

可以直接在 Git Bash 中用命令打开：

或者手动找到该文件，用 Typora 打开。Typora 的实时渲染能让你专注写作，插入图片也很方便（建议将图片放在 source/images 文件夹，或使用图床）。

2️⃣ 本地预览（边写边看）

在博客根目录启动本地服务器：

浏览器访问 http://localhost:4000，即可实时预览效果。保存文章后，刷新页面就能看到更新（部分主题可能需要重启服务器）。

3️⃣ 生成静态文件

写作完成并确认无误后，生成最终用于部署的静态网页：

这会生成 public 文件夹，里面就是完整的网站文件。

4️⃣ 部署到 GitHub Pages

确保 _config.yml 中 deploy 配置正确（之前已确认），然后执行：

它会自动将生成的静态文件推送到你指定的 GitHub 仓库分支（通常是 main 或 gh-pages），稍等片刻，你的博客（https://用户名.github.io）就会更新。

5️⃣ （可选）备份博客源码

建议将整个博客文件夹（除了 node_modules 和 public）用 Git 管理，推送到 GitHub 仓库的另一个分支（比如 source 分支），这样即使电脑损坏，也能快速恢复环境。

以后每次写完文章，除了 hexo d 部署，也记得执行 git push 备份源码。

日常写作循环总结

步骤 命令 说明
新建文章 hexo new 标题 生成 Markdown 文件
编辑 Typora 打开 写作、插入图片
预览 hexo s 本地实时查看
生成 hexo g 编译静态文件
部署 hexo d 发布到 GitHub Pages
备份源码 git add . → git commit → git push 可选但推荐

小贴士

  • 图片处理：可以将图片统一放在 source/images 文件夹，文章中使用 ![](/images/图片名.png) 引用。
  • 标签/分类：在文章 Front-matter 中添加 tags: 和 categories:，便于归档。
  • 草稿功能：使用 hexo new draft "标题" 创建草稿，预览时用 hexo server --draft，发布前用 hexo publish 标题 移入 _posts。
  • 主题配置：如果想修改主题样式或添加插件，修改 _config.yml 后重新生成即可。
